# Архиватор ZIP

Настольное приложение для Windows: упаковка файлов и папок в ZIP-архив и распаковка существующих архивов через графический интерфейс с индикатором прогресса и возможностью отмены операции.

Стек: **C# / .NET 8 · Windows Forms · System.IO.Compression · xUnit**.

## Возможности

- добавление отдельных файлов и целых папок — кнопками или перетаскиванием в окно (drag-and-drop);
- упаковка в ZIP с выбором степени сжатия: без сжатия, быстрое, оптимальное, максимальное;
- распаковка любых ZIP-архивов с сохранением структуры папок;
- индикатор прогресса: проценты, обработанный объём, имя текущего файла;
- отмена длительной операции в любой момент — недописанный архив удаляется;
- защита от атаки **Zip Slip** при распаковке (записи вида `../../file` отклоняются);
- корректная обработка пустых папок и совпадающих имён файлов (`a.txt`, `a (2).txt`);
- интерфейс не блокируется во время работы: операции выполняются в фоновом потоке.

## Структура решения

```
ZipArchiver.sln
├── src/ZipArchiver.Core         — логика работы с архивами, не зависит от интерфейса
│   ├── ArchiveService.cs        — упаковка и распаковка с прогрессом и отменой
│   ├── ArchiveProgress.cs       — модель состояния операции
│   └── ByteSize.cs              — форматирование размеров (Б/КБ/МБ/ГБ)
├── src/ZipArchiver.App          — графический интерфейс (WinForms)
│   ├── MainForm.cs              — логика главного окна
│   └── MainForm.Designer.cs     — разметка элементов управления
└── tests/ZipArchiver.Core.Tests — модульные тесты ядра (xUnit)
```

## Сборка и запуск

Требуется [.NET SDK 8.0](https://dotnet.microsoft.com/download/dotnet/8.0) или Visual Studio 2022 с рабочей нагрузкой «Разработка классических приложений .NET».

```bash
# запуск приложения (Windows)
dotnet run --project src/ZipArchiver.App

# сборка всего решения
dotnet build

# модульные тесты (работают на любой ОС)
dotnet test
```

В Visual Studio: открыть `ZipArchiver.sln` → F5.

Графический интерфейс запускается только под Windows; ядро `ZipArchiver.Core` и тесты кроссплатформенны. Сборка решения на macOS/Linux (например, в CI) возможна благодаря свойству `EnableWindowsTargeting`.

## Как это устроено

- **Разделение слоёв.** Вся работа с архивами собрана в `ArchiveService` (проект `ZipArchiver.Core`), который ничего не знает о формах — поэтому логика покрыта модульными тестами, а интерфейс остаётся тонким.
- **Отзывчивый интерфейс.** Операции запускаются через `Task.Run` и ожидаются с `async/await`, поток интерфейса не блокируется.
- **Прогресс.** Сервис сообщает о ходе работы через `IProgress<ArchiveProgress>`; класс `Progress<T>` сам переправляет уведомления в поток интерфейса (без ручного `Invoke`). Отчёты отправляются только при изменении процента, чтобы не перегружать форму.
- **Отмена.** Стандартный механизм `CancellationToken`: кнопка «Отменить операцию» взводит токен, копирование прерывается, недописанный архив удаляется.
- **Безопасность распаковки.** Каждый путь записи нормализуется и проверяется на принадлежность папке назначения — защита от Zip Slip.
- **Точный план упаковки.** Список записей собирается до открытия файла архива: заранее известен общий объём (для процентов), а архив не может включить сам себя.

## Тесты

`dotnet test` — 7 тестов: круговой цикл «упаковал → распаковал», сохранение пустых папок, уникальность совпадающих имён, монотонность прогресса до 100 %, удаление недописанного архива при отмене, отклонение записей Zip Slip, обработка повреждённого архива.
